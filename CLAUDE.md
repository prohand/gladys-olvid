# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Gladys Assistant **external integration** of type `communication` (Node 22+, ESM, no build
step) that lets users chat with their home from [Olvid](https://olvid.io), the end-to-end
encrypted messenger — like the Telegram integration: questions answered by the Gladys brain,
scene notifications in the same discussion. No devices, no discovery screen. Olvid is used in its
consumer version (no Enterprise, no Keycloak).

Runtime dependencies: `@gladysassistant/integration-sdk`, `@olvid/bot-node` (official gRPC client)
and `@bufbuild/protobuf`.

```
Olvid app ──E2EE──► olvid/bot-daemon ──gRPC──► this integration ──WS/HTTP──► Gladys
 (phone)            (sub-container run         (container)
                     by Gladys)
```

```bash
npm install
npm test                                   # node --test (built-in runner)
node --test test/daemon.test.js            # one file
node --test --test-name-pattern "link"     # one test by name
npm run lint                               # eslint .
npm run format:check                       # prettier --check . (CI gate)
npm run format                             # prettier --write .
```

CI runs `format:check`, `lint`, `test`. Releases: **Actions → Release** only (bumps
`package.json`, manifest `version` + `docker_image`, re-runs Prettier, tags, builds).

## Architecture

```
index.js                 SDK wiring: session lifecycle, managed daemon, status reporting
src/config.js            daemon mode (managed / own), internal keys, requiresReconnect()
src/olvid/container.js   the managed daemon sub-container: start/stop/watch, admin key, volumes
src/olvid/daemon.js      OlvidDaemon: gRPC session, reconnection backoff, send/receive, settings
src/olvid/attachments.js attachments handling
src/olvid/identifiers.js contact key helpers (shortened in logs)
src/messaging.js         incoming message -> link code or Gladys message; contact languages
src/actions.js           Configuration screen buttons (invitation link, link account...)
src/i18n.js, src/text.js channel texts in the contact's language, truncation
```

### Invariants worth knowing

- **Gladys runs the daemon itself**: it is declared in the manifest `containers` field
  (`olvid-daemon`, `start: "manual"`, volumes `/daemon/data` and `/daemon/backups`) and started
  with `gladys.startContainer()`. Its gRPC API is only reachable on the integration's private
  network (`MANAGED_DAEMON_URL`); no port is published.
- **The daemon admin key is generated by the integration** on first run and passed through the
  runtime `env` of `startContainer` (the manifest is public). It and the bot client key are
  stored outside `config_schema` (`INTERNAL_CONFIG_KEYS`) via `gladys.setConfig()` — never shown
  in the UI, never logged. `setConfig` does not echo back through `onConfigUpdated`, so
  `saveInternalConfig` also updates the in-memory config.
- **"My own daemon" mode** takes a URL and an admin key from the form instead; switching mode
  stops the managed container.
- **Linking**: an unlinked contact sends the short code Gladys shows; `gladys.linkContact()`
  ties the Olvid contact to the Gladys user, whose language is then used for replies. A 404 from
  `publishMessage` means "not linked".
- **The session survives a Gladys disconnection** (the Olvid side keeps running); a stopped
  daemon container is detected and restarted (`createDaemonContainerWatch`), and the connection
  status explains the container state rather than a bare "unreachable".
- **Every gRPC call is bounded** (`RPC_TIMEOUT_MS`, `withTimeout` in `daemon.js`):
  `@olvid/bot-node` sets no deadline and no HTTP/2 keepalive, so a daemon gone without
  closing the connection would otherwise hang the ping, a send or a connection attempt
  forever. Admin and key-checking clients are stopped once provisioning is done.
- **A Gladys reconnection keeps an open Olvid session** (`shouldRestartSession`): it is
  only restarted when it is down or a session setting changed.
- **Unlinked contacts are rate-limited** (`createLinkAttemptLimiter`, 5 messages / 15 min,
  then silence): invitations are accepted automatically by default.
- User-facing messages are bilingual `{ en, fr }`; contact keys are shortened in logs.

### Manifest

`test/manifest.test.js` keeps `gladys-assistant-integration.json` (config schema, actions,
`containers`, `messaging`) in sync with `DEFAULT_CONFIG` and the action handlers. The daemon
image tag in `containers` and `@olvid/bot-node` should move together.

## Testing

No network and no Docker: `test/helpers/fakeOlvid.js` fakes the daemon client,
`test/helpers/fakeGladys.js` the SDK (containers included).

## Conventions

Prettier formats, ESLint catches mistakes. Comments and JSDoc explain **why**. User docs in
`docs/en.md` and `docs/fr.md`, kept in sync. The integration's own rootfs is read-only.
